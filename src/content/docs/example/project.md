โปรแกรมก่อนหน้าทำงานเมื่อมีชื่อ แต่ถ้าชื่อมีแต่ช่องว่างจะได้ข้อความทักทายที่ไม่มีชื่อ บทนี้จะเพิ่มกติกาว่าชื่อต้องไม่ว่าง และแสดงวิธีรับมือเมื่อข้อมูลไม่ถูกต้อง โดยใช้โปรเจกต์เดิม

## กำหนดพฤติกรรม

เราจะตัดช่องว่างหัวท้ายของชื่อก่อนสร้างข้อความ หากไม่มีตัวอักษรเหลือ ฟังก์ชันจะส่งข้อผิดพลาดออกไปให้ผู้เรียกจัดการ ตารางนี้คือผลที่เราจะตรวจ:

| ข้อมูลเข้า | พฤติกรรมที่ต้องได้ |
| --- | --- |
| `Developer` | ได้ข้อความทักทายตามเดิม |
| `  Developer  ` | ได้ข้อความทักทายโดยไม่มีช่องว่างหัวท้าย |
| ช่องว่างสามตัว | แสดงข้อความแจ้งว่ากรุณาระบุชื่อ |

## ปรับฟังก์ชันเดิม

เปิด `index.ts` แล้วปรับฟังก์ชัน `greet` เป็นโค้ดต่อไปนี้ บรรทัดเรียกใช้เดิมให้คงไว้ใต้ฟังก์ชัน:

```ts title="index.ts — ฟังก์ชันที่ปรับแล้ว"
export function greet(name: string): string {
  const displayName = name.trim();

  if (displayName.length === 0) {
    throw new Error('กรุณาระบุชื่อ');
  }

  return `สวัสดี, ${displayName}!`;
}
```

`trim()` คืนข้อความใหม่ที่ตัดช่องว่างหัวท้ายออก โดยไม่เปลี่ยนค่าเดิม เมื่อ `length` เท่ากับศูนย์ เราใช้ `throw` ส่ง `Error` ออกไป การทำงานของฟังก์ชันจะหยุดตรงนั้นและไม่ไปถึง `return`

การระบุ `string` ตรวจได้ว่าค่าเป็นข้อความในขั้นตอนตรวจชนิด แต่ไม่ได้ยืนยันว่ามีตัวอักษรอยู่ภายใน กติกาเรื่องชื่อว่างจึงต้องตรวจตอนโปรแกรมทำงานด้วย

## รับข้อผิดพลาดที่จุดเรียกใช้

แทนที่บรรทัดเรียกใช้เดิมด้วยการเรียกสามกรณีด้านล่าง กรณีที่คาดว่าจะผิดพลาดอยู่ภายใน `try` และใช้ `catch` แสดงข้อความที่อ่านรู้เรื่อง พิมพ์ให้ไฟล์สุดท้ายเป็นดังนี้:

```ts title="index.ts — ไฟล์ที่พร้อมรัน"
export function greet(name: string): string {
  const displayName = name.trim();

  if (displayName.length === 0) {
    throw new Error('กรุณาระบุชื่อ');
  }

  return `สวัสดี, ${displayName}!`;
}

console.log(greet('Developer'));
console.log(greet('  Developer  '));

try {
  console.log(greet('   '));
} catch (error) {
  if (error instanceof Error) {
    console.log(error.message);
  } else {
    throw error;
  }
}
```

ค่าที่ `catch` รับมาอาจไม่ใช่ `Error` เสมอไป เราจึงตรวจด้วย `instanceof Error` ก่อนอ่าน `message` และส่งข้อผิดพลาดชนิดอื่นต่อด้วย `throw error` แทนการซ่อนปัญหาที่ไม่คาดคิด

## รันและเทียบผล

บันทึกไฟล์ แล้วรันจากโฟลเดอร์ `greeting`:

```sh
npx tsc index.ts --target ES2022 --module NodeNext --outDir dist --strict
node dist/index.js
```

ควรได้สามบรรทัดนี้ตามลำดับ:

```text title="ผลลัพธ์"
สวัสดี, Developer!
สวัสดี, Developer!
กรุณาระบุชื่อ
```

สองบรรทัดแรกตรงกันเพราะเราตัดช่องว่าง ส่วนบรรทัดสุดท้ายมาจาก `catch` ไม่ใช่ `return` หากโปรแกรมหยุดพร้อม stack trace ให้ตรวจว่าการเรียกด้วยชื่อว่างอยู่ใน `try` และแปลงไฟล์ใหม่แล้ว

## ก่อนจบหนังสือตัวอย่าง

ตอนนี้เราเตรียมเครื่องมือ เขียนฟังก์ชัน แปลงและรันโปรแกรม รวมถึงตรวจข้อมูลและจัดการข้อผิดพลาดครบหนึ่งลำดับงาน หนังสือจริงควรใช้รูปแบบเดียวกัน: ระบุไฟล์ที่แก้ อธิบายเหตุผล พาพิมพ์ทีละช่วง แล้วให้ผลที่ตรวจเทียบได้ทันที

เนื้อหานี้จบในหน้าหนังสือ ไม่ต้องเปิดโปรเจกต์เฉลยหรือดาวน์โหลดไฟล์เพิ่มเติม ผู้เขียนสามารถเปลี่ยนภาษาและหัวข้อได้โดยรักษาลำดับการอธิบายนี้ไว้
